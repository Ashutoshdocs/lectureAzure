# Python Flask Application on Azure App Service (FTPS Deployment)

A simple, responsive Python Flask application with a modern HTML/CSS
dashboard. This project is designed for an Azure App Service practical:
build and test a Flask application locally, deploy its files to Azure,
configure the startup command, and verify the live website.

## 1. Project overview

The application includes:

-   A responsive HTML page with a modern gradient and glass-style cards.
-   A Python Flask backend.
-   Dynamic server information: Python version, hostname, and server
    time.
-   A `/health` endpoint that returns JSON.
-   Gunicorn as the production WSGI server.

## 2. Project structure

``` text
azure-python-webapp/
├── app.py
└── requirements.txt
```

## 4. Run the application locally

Run these commands on Ubuntu or another Python-enabled machine:

``` bash
mkdir azure-python-webapp
cd azure-python-webapp
```

Create the two files shown above in this directory, then create a
virtual environment and install dependencies:

``` bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

Start the development server:

``` bash
python app.py
```

Open these URLs on the same machine:

-   Home page: `http://localhost:8000/`
-   Health endpoint: `http://localhost:8000/health`

To test from another machine on the network, use the Ubuntu VM's
reachable IP address instead of `localhost`, and ensure its firewall or
network security rules permit the port.

## 5. Create the Azure Web App

In the Azure Portal:

1.  Create a Resource Group.
2.  Create an App Service Plan and select **Linux**.
3.  Create a Web App.
4.  Select **Code** as the publish option.
5.  Select **Python** as the runtime stack and choose a supported Python
    version.
6.  Select the region and App Service Plan appropriate for the
    practical.
7.  Create the Web App.

After creation, note the default hostname, for example:

``` text
https://YOUR-WEBAPP-NAME.azurewebsites.net
```

## 6. Configure the startup command

In the Azure Portal, open:

**App Service → Settings → Configuration → General settings → Startup
Command**

Use:

``` bash
gunicorn --bind=0.0.0.0:8000 app:app
```

The command means:

-   `gunicorn`: starts the production WSGI server.
-   `--bind=0.0.0.0:8000`: listens on all network interfaces on port
    8000.
-   `app:app`: imports the Flask application object named `app` from
    `app.py`.

Save the configuration. Restart the Web App if required.

## 7. Deploy using FTPS

> **Important:** Azure App Service FTP deployment uses FTPS for
> encrypted file transfer. Do not use unencrypted FTP. Availability and
> configuration of FTP/FTPS deployment credentials depend on the App
> Service configuration and deployment policy.

1.  Open the Web App in the Azure Portal.
2.  Open **Deployment Center** and locate the FTPS/deployment
    credentials information (the exact portal layout can vary).
3.  Obtain the FTPS endpoint and deployment credentials. Use the
    credentials and endpoint provided by Azure; do not assume the Azure
    portal login password is the FTP password.
4.  Connect with an FTPS-capable client such as FileZilla, using the
    secure FTP protocol and the hostname, username, and password
    supplied by Azure.
5.  Open the application directory:

``` text
/home/site/wwwroot/
```

6.  Upload the application files so that the directory contains:

``` text
/home/site/wwwroot/
├── app.py
└── requirements.txt
```

Do not upload the local `venv` directory. It is not required and should
not be copied to the App Service.

## 8. Install Python dependencies and build the deployment

**Uploading files through FTPS does not install Python packages.** The
application needs Flask and Gunicorn available in its runtime
environment.

For a reliable Python App Service deployment, use an Azure-supported
build/deployment workflow that runs Oryx build automation and installs
packages from `requirements.txt`. For example, use ZIP deployment with
build automation enabled:

``` bash
az webapp config appsettings set \
  --resource-group YOUR-RESOURCE-GROUP \
  --name YOUR-WEBAPP-NAME \
  --settings SCM_DO_BUILD_DURING_DEPLOYMENT=true
```

Then deploy a ZIP package containing `app.py` and `requirements.txt`
through an appropriate App Service ZIP deployment workflow. Allow the
remote build to complete before starting the application.

If your exercise specifically requires FTPS, upload the source files
using FTPS, but arrange dependency installation through a supported
build/deployment process. Do not assume that an FTPS upload alone
performs an Oryx build or installs `requirements.txt`.

## 9. Verify the deployment

After the deployment and dependency installation are complete:

1.  Restart the Web App if necessary.
2.  Open the default Web App hostname.
3.  Confirm that the dashboard loads.
4.  Open the health endpoint.

``` text
https://YOUR-WEBAPP-NAME.azurewebsites.net/
https://YOUR-WEBAPP-NAME.azurewebsites.net/health
```

Expected health response (the hostname value will vary):

``` json
{
  "status": "healthy",
  "application": "PanamaTech Academy",
  "backend": "Python Flask",
  "hostname": "..."
}
```

## 10. Troubleshooting

  ------------------------------------------------------------------------------------
  Symptom                                          What to check
  ------------------------------------------------ -----------------------------------
  HTTP 500 error                                   Check App Service logs; verify
                                                   Flask is installed and the startup
                                                   command is correct.

  Application fails to start                       Confirm `app.py` is in
                                                   `/home/site/wwwroot/` and contains
                                                   an object named `app`.

  `ModuleNotFoundError: No module named 'flask'`   Ensure the deployment build
                                                   installed packages from
                                                   `requirements.txt`.

  Gunicorn command not found                       Confirm Gunicorn is listed in
                                                   `requirements.txt` and the build
                                                   completed successfully.

  Default page appears                             Verify the files were uploaded to
                                                   the correct `wwwroot` directory and
                                                   restart the app.

  FTPS connection fails                            Verify the FTPS endpoint,
                                                   deployment credentials, network
                                                   access, and FTPS settings.

  Changes are not visible                          Confirm the latest files were
                                                   deployed, then restart the Web App
                                                   and refresh the browser.
  ------------------------------------------------------------------------------------

For diagnostics, use **App Service → Monitoring → Log stream** and the
deployment logs available in the portal.

## 12. Key teaching point: What does Azure manage?

With Azure App Service, Microsoft manages the underlying hosting
infrastructure and platform operations. You focus on your application
code, runtime configuration, dependencies, and application behavior.
Unlike deploying to a self-managed Azure Virtual Machine, you do not
normally log in to or administer the underlying App Service host VM.
