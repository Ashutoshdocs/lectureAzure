🔐 What is a Private Endpoint?

A Private Endpoint is a network interface placed in your Azure Virtual Network that provides a private IP address for accessing an Azure service that supports Azure Private Link.

Important: The private IP belongs to the Private Endpoint network interface. It is not a new NIC attached to the Storage Account.

For a Storage Account, the endpoint can target a specific sub-resource such as the blob service.

🌐 Public Endpoint vs Private Endpoint

Public EndpointPrivate Endpoint
Service is reached through its public endpoint. Client reaches a private IP associated with the Private Endpoint.
Example: Storage public hostname. Example: Storage hostname resolves privately through Private DNS.
Public network access can be controlled by service settings and network rules. Private connectivity can be used and public access can subsequently be disabled.

📛 Why DNS is so important

Private Endpoint connectivity is closely tied to DNS. The goal is normally to let applications continue using the familiar service hostname while DNS returns the private endpoint address from inside the VNet.

Application | | mystorageaccount.blob.core.windows.net v DNS resolution | v Private DNS configuration | v Private IP of Private Endpoint | v 10.0.2.4 | v Private Endpoint | v Azure Storage

For Blob Storage, the private DNS zone commonly used is:

privatelink.blob.core.windows.net

🔗 Private Endpoint vs Private Link Service

Private EndpointPrivate Link Service
Consumer-side private entry point. Provider-side mechanism for publishing a service privately.
Gets a private IP in the consumer VNet. Usually fronts a provider service through an Azure Load Balancer.
Used to privately consume supported Azure or Private Link-enabled services. Used when a provider wants to expose its own service through Private Link.
For this Storage Account demo: You create the Private Endpoint. You do not create your own Private Link Service for Azure Storage.

🧪 Demo sequence

1. Deploy the VM

Place a VM in a VNet. The VM will be the client used to test Storage connectivity.

2. Create the Storage Account

Create a Storage Account and enable the Blob service. Initially, keep the network configuration suitable for the first connectivity test.

3. Test public access

From the VM, verify access to the Storage Account and record the DNS behavior.

4. Create the Private Endpoint

Create a Private Endpoint for the Storage Account and select the Blob sub-resource.

5. Check the assigned private IP

Open the Private Endpoint and identify its network interface and private IP address.

6. Configure Private DNS

Configure the appropriate Private DNS Zone and link it to the VNet.

7. Test DNS from the VM

Verify that the Storage hostname resolves to the Private Endpoint private IP from inside the VNet.

8. Test Storage connectivity

Verify that the VM can access the Blob service through the private path.

9. Disable public access

After private connectivity is confirmed, disable public network access for the Storage Account.

10. Test again

The VM should continue accessing the Storage Account through the Private Endpoint.

Proof: If the VM continues to access Storage after public network access has been disabled, while DNS resolves the service through the Private Endpoint, the lab demonstrates private connectivity.

💡 The most important concept

The Private Endpoint is not the Storage Account.
It is a private network interface in your VNet that provides a private entry point to the Storage service.

🎓 One-minute explanation

"A Private Endpoint gives an Azure service a private entry point inside my VNet. Azure creates a network interface for that endpoint and assigns it a private IP. My VM resolves the Storage Account hostname to that private IP through Private DNS. The VM then connects to the Private Endpoint, and Azure Private Link carries that connection to the Storage service. I do not need to create a Private Link Service for Azure Storage because Storage is already an Azure service that supports Private Link."
